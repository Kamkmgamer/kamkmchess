# KHA-43 browser cloud integration boundary

`src/cloud/` provides typed Go API transport, archive batch conversion, per-account checkpoint/credential-echo gates, Web Locks coordination with a transactional IndexedDB lease fallback, cross-tab notices, explicit conflict preservation, takeover snapshots, and delete hooks. The browser uses only the `/v1` HTTP API. API requests use the caller's Clerk bearer token, omit browser credentials, reject redirects, and require HTTPS except localhost development.

The transport covers the documented game read/create/commit/takeover/delete routes, idempotent operation lookup, and full archive-batch read. Create sends a revision-1/epoch-1 seed checkpoint with empty archive references because the Go create contract accepts no archive batch. The sync manager then commits a translated full checkpoint plus the complete initial archive before recording acknowledgement. It never advances the acknowledged archive cursor until the archive commit is accepted or an operation receipt confirms it.

`createIndexedDbCloudLocal` is a durable `CloudLocalPort` implementation stored in an account-scoped IndexedDB database. It reserves a stable operation ID by game/checkpoint revision, tracks acknowledgement revision/epoch/checkpoint revision and event/chunk cursors, saves full local conflict snapshots and accepted cloud checkpoint/archive snapshots, and writes owner tombstones before deleting local game/outbox rows. It reads and deletes through the `AccountGameRepository`, which keeps guest and account stores separate. Operation metadata is durable across adapter recreation; the sync caller must still retry with the same checkpoint revision until the receipt is accepted.

Explicit takeover fetches and validates the accepted cloud checkpoint and complete archive batch, stores the current local continuation as a separate conflict, then invokes the Go compare-and-swap takeover. The wrapper adopts the accepted snapshot into a separate physical database using `prepareOwnershipTakeover`, leaving the prior continuation saved. Go advances the record epoch without rewriting checkpoint JSON; the client accepts that older checkpoint epoch and the adoption helper rebinds local request and analysis authority to the new epoch. Archive digests, sequence order, identity and quarantine are checked before adoption. Cloud delete calls the owner-scoped Go delete before invoking local cache/outbox/tombstone cleanup.

The manager writes a pending takeover marker before the remote operation. It installs the accepted local continuation before atomically recording the cloud acknowledgement and clearing that marker. After a crash, an explicit Sync resumes this adoption transition before it can commit any local branch. The `beforeTakeoverAdoption` hook lets the wrapper dispose the old controller and database handle. The wrapper opens the installed continuation after success; it must not import the snapshot a second time.

## Evidence and remaining integration

Focused fixtures check secure request options, identity/credential/quarantine rejection, Go archive DTO mapping, simulated revision conflict preservation, IndexedDB lease ordering, durable operation ID reuse, sync metadata, archive snapshot/conflict storage and deletion tombstones. `AccountWorkspace` wires the manager to explicit Sync and Takeover actions and public configuration. It lists account games already saved on this device. Automatic sync and browsing/downloading games from another device are not implemented in this UI. No real multi-tab/device, network-partition, deployed API, or deletion journey has run. Staging stays disabled by default; no database or Clerk infrastructure was provisioned by this work.
