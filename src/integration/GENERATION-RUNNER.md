# Generation composition runner

`runGenerationTurn` composes one model request outside the UI. The caller must supply `expectedProfileConfigRevision`, the hash revision bound to its validated model selection or diagnostic. The runner checks it against the loaded connection profile before reading consent or credentials and before transport. The model selection's numeric `configurationRevision` is a separate controller revision and must never be used to infer this hash. The runner then verifies that the selected provider, connection, protocol, route, disclosure consent, and bound credentials still match, composes retained history with the fresh position and clock, encodes the selected protocol, checks capacity, and makes one injected transport call. It dispatches only a complete authored answer as a model turn effect; an explicit resignation inside that answer can lose the game. Protocol-level provider refusals, failures, incomplete output, and abort dispatch a fenced interruption. Abort cancels an in-progress response body read. The runner does not retry.

Completed results always include `recovery: { kind: 'automatic' | 'paused'; detail: string } | null`. The UI may continue generation only when `dispatch === 'accepted'` and `recovery.kind === 'automatic'`; it should surface `paused.detail` as the reason Retry, Replace, or Resume is needed. Legal moves, resignation, the fourth illegal move loss, rejected or stale effects, and terminal games return `null`. A nonterminal illegal attempt returns automatic recovery with the controller's violation feedback. Current model formatting corrections return automatic recovery through the three correction budget; exhausted corrections return paused recovery. A queued candidate's first formatting failure is recorded as failed in the handoff and returns paused recovery immediately.

Correction and illegal-move feedback is appended as a retained user-role history message in the same checkpoint transaction as the classified effect and archive event. The next generation request therefore replays the exact correction text with event and segment attribution. Feedback contains only the format instruction or violation explanation, never a legal-move list or a selected alternative. Usage accounting still records these provider calls as `move`: its durable terminal record is written before the answer is classified, so labeling a request as a correction from transient UI state would be inaccurate.

The result includes the raw protocol stream (including decoder raw events and usage records) and a request-scoped usage summary under the same stable request ID. Usage is labeled `EPHEMERAL NOT PERSISTED`: current storage has no usage journal, so closing or reloading the app loses this accounting. Estimates require a complete normalized provider usage shape and an explicitly supplied rate card; the runner currently has no rate-card source and returns `unknown` cost status while preserving provider raw usage. Provider charges are not independently verified.

Capacity rejection occurs before transport and is treated as a failed turn request. A late completion after Stop may still be returned for diagnostics, but its effect dispatch is rejected by the controller fence and cannot change the game.
