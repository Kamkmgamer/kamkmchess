# Fixture entry points

Run `npm test` once or `npm run test:watch` while developing. Vitest runs Node-based offline fixtures in `src/**/*.test.ts`, `src/**/*.test.tsx` and `tests/**/*.test.ts`. Experiments and the disposable prototype are excluded. Run one file with `npm test -- path/to/file.test.ts`.

The suite includes product fixtures for strict rules, pure clocks, proof checking, cooperative graph search, serialized controller decisions, archive validation, IndexedDB storage, provider connections and provider protocols. `npm test` fails when no matching fixtures exist. Run `npm test -- tests/providers/connections` for connection profiles, catalog handling, request preparation, disclosure, route scope and store behavior. Run `npm test -- src/controller/index.test.ts` for the controller, `npm test -- src/rules/rules.test.ts` for rules, `npm test -- src/clocks/index.test.ts` for clocks, `npm test -- src/proofs/checker.test.ts` for proofs, `npm test -- src/proofs/search/search.test.ts src/storage/proof-search.test.ts` for graph search and durable search checkpoints, `npm test -- src/archive/archive.test.ts` for archives or `npm test -- src/storage/storage.test.ts` for game storage. Run the protocol fixtures together with `npm test -- src/providers/protocols/chat-completions.test.ts src/providers/protocols/responses.test.ts src/providers/protocols/anthropic-messages.test.ts`. They use synthetic data and send no provider requests. Deterministic coverage remains separate from product acceptance.

The approved [module handoff](../docs/spec/mvp-handoff.md#implementation-sequence-and-module-handoff) and [module guide](../docs/architecture/modules.md#verification-seams) identify the controller, strict rules, clock/checkpoint, archive/replay, connection, protocol, proof-checker and search seams. See [KHA-29 controller evidence](../docs/implementation/KHA-29-controller-evidence.md), [KHA-31 proof-search evidence](../docs/implementation/KHA-31-evidence.md), [KHA-34 connection evidence](../docs/implementation/KHA-34-evidence.md) and [KHA-35 protocol-core evidence](../docs/implementation/KHA-35-evidence.md) for their fixture and build records. Use TDD for behavior at those interfaces. Write one failing test, implement that behavior, and rerun its file and typechecking before the next slice. Run the full suite once before completing a ticket.

Use independent expected positions, counters, deadlines and wire records. Preserve an acceptance ID in fixture descriptions when applicable. Cover aborts, invalid inputs and stale identities at the relevant seam. Never replace native/AT/live evidence with these deterministic fixtures. No test needs a real provider key, account or paid request.

KHA-32 fixtures run with `pnpm exec vitest run src/controller src/adjudication src/adjudication-controller`. They cover setup classification, pending event ordering, bounded Worker execution and cancellation through the controller. The [browser smoke helper](../experiments/adjudication-controller/README.md) additionally exercises the actual module Worker and native IndexedDB reopen through Vite. See [pending adjudication evidence](../docs/implementation/KHA-32-pending-adjudication.md) for scope and limitations.

KHA-33 fixtures run with `pnpm exec vitest run src/controller`. They drive Undo, the practice boundary and restart/rematch separation through the public controller API with an injected store and time source. The adjudication queries raised by each move are settled with checked mating witnesses that the controller re-verifies, so no proof search runs in that file. See [guest lifecycle evidence](../docs/implementation/KHA-33-lifecycle.md).
